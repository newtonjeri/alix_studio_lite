## Install and start Lite

Install once, on any platform. This builds `.venv` in the Lite folder from `requirements.txt`, then runs a check (see the README):

```bash
cd alix_studio_lite
python3 tools/setup_lite.py         # Python 3.12 to 3.14. Windows: py tools\setup_lite.py (py -3.14 if a newer Python is the default)
```

Then Lite starts the same way as ALIX Studio. The launcher uses `.venv` by itself:

```bash
cd alix_studio_lite/tools
./run_lite.sh                  # the Lite UI at http://127.0.0.1:8766/   (Ctrl+C to stop)
./run_lite.sh --ui legacy      # Legacy Lite at http://127.0.0.1:8766/legacy/
./run_lite.sh --no-browser     # or --port 8800, --data DIR, --fixture commode_b (Legacy Lite)
./run_lite.sh --set-pin engineer   # change the operator or engineer PIN
```

- Port 8766 is used, so Lite can run beside ALIX Studio (8765).
- **Stopping Lite:** Ctrl+C (or the system monitor's End) sends STOP to the arms, gives each controller its speed back and lets the links go, within 30 s. Once STOP is out, Ctrl+C again quits at once. The arms' connection processes leave Ctrl+C to the server, so the STOP passes through them (21 October: before this, they died of the Ctrl+C with a traceback each and the exit's STOP was not confirmed); an arm whose controller does not confirm it is said in the terminal. Past 30 s Lite quits as it is, first writing what each thread was doing to `Resources/Logs/<day>/threads-HHMMSS.txt`. If Lite ever stops answering, `kill -USR1 <process>` (the start-up lines give the number) prints what each thread is doing: send that with the day's logs.
- The Lite UI's projects are in `Resources/Projects/` in the repository (16 October; `--projects`), each in a folder named exactly as the project was named when it was created. A rename later keeps the folder's name.
  - The first start of this version copies the projects kept by id in `~/ALIX-Lite/projects/<id>/` into it, once. The old folders stay where they are, as a backup.
  - A copied project whose name cannot name a folder (a character such as `/ \ :`, or a name Windows keeps), or that another folder already has, gets a name that can (the start-up lines and the activity log say which).
  - These folders are not committed: `git clean -x`, or deleting the clone, deletes them. Keep a project file (`.alixproj`) of any project you need, or commit them (see `.gitignore`).
- Everything else Lite keeps stays in `~/ALIX-Lite/` (outside the repository): this computer's last project and the projects' trash (`projects/`), the Trajectory Viewer's files, the PINs and the settings;
  - Legacy Lite's projects in `legacy/projects/<fixture>/`. The first start of an earlier version moved them there from `projects/`.
- The operator PIN (log-in) and the engineer PIN (Advanced Robot Controls, and Legacy Lite's engineer role) are both `1234` until changed. They are stored hashed in `~/ALIX-Lite/auth.json`. Legacy Lite asks for the same operator PIN: every request but STOP needs the session, in both UIs.
- Legacy Lite's first start creates the **Commode C (demo)** project. It holds the commode C test recordings, assigned to 8 left-arm regions.
- The robot is a **stand-in** until robot I/O is built: every robot screen works and nothing moves. The Lite UI's status pill and Legacy Lite's grey line under the top bar say so.

## Findings to carry forward

- **From the lab's logs (16 October).** Real playback took about 5.7 ms a line (5 ms asked). Uploads ran at about 31 kB/s. The controller answered 4105 after some runs that broke L2. Runs at 1 % speed were refused. The hand's thumb channel stopped on the tool (counted as done: settled). The LEFT controller held 183–187 global points and 79 programs, the RIGHT 68 points.
- **G5 cannot be a hard limit.** ALIX's predicted-departure model reads 33–109 mm on the raw commode C recordings themselves, which ran fine on the robot. Lite shows it as a warning (C1). A region's MAX DEV tightens the path-accuracy limit (L5) instead.
- **TOPP-RA moved the end pose.** ALIX's 30 mm arc-length smoothing moves the last pose by up to 0.06°. Lite pins both ends back to the recording over the last 30 mm, so L6 (0.05°) holds.
- **Controller speed envelope (for robot I/O).** The controller's TCP speed settings default to 0.25 m/s. ALIX raised them to 1.5 m/s for its replays and restored them after (`vendor/alix/.../alix_dispatch/limits.py`, `guard`). Runner v14 never touches them. TOPP-RA files move the hand at up to about 0.9 m/s. This must be checked on the robot before fast files are run.
